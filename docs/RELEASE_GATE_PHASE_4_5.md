# Release gates — phases 4 and 5

These phases remove the two source-tree causes of the red Application job and make the protected-route cache policy part of the generated deployment configuration.

## Phase 4 — green source tree

- The tracked `.env` is removed. Runtime values belong in the Lovable/hosting secret manager; `.env.example` remains the contract.
- `src/routeTree.gen.ts` is regenerated by the production build and included in the release.
- The release guard continues to reject tracked environment files and recognised credentials.

The Google Maps browser key previously committed to the public repository must still be rotated and restricted. Deleting the file does not remove its old value from published history and published Lovable history must not be rewritten.

## Phase 5 — edge cache enforcement

- `src/lib/private-cache.ts` is the shared list of private route families and cache headers.
- `src/server.ts` applies that policy to application responses.
- `nitro.config.ts` applies the same policy to Nitro and the generated Cloudflare/Lovable `_headers` output.
- `npm run verify:build-output` fails CI if any protected route family loses `private, no-store` edge configuration.
- `npm run preview` uses Nitro's production preview so it exercises the generated deployment server rather than Vite's obsolete `dist/server` path.

## Required release sequence

1. Upload this release while preserving folders and delete `.env` from GitHub.
2. Commit normally; do not force-push, rebase or rewrite Lovable history.
3. Confirm both Production checks jobs and CodeQL pass.
4. Rotate/restrict the Google Maps browser key and populate production secrets outside Git.
5. Redeploy the exact passing commit.
6. Run Production smoke, then Release candidate evidence.
7. Complete and record every mandatory item in `docs/GO_LIVE_CHECKLIST.md` before enabling unrestricted customer payments.
